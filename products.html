Data products

Files a client can request.

Display, internal use, and redistribution are set in the scope. Freshness is a final result, a periodic file, or in-play events, with no promised speed.

Scores Fixtures Live events Reference Historical results

01

Scores

Contains
Final and in-progress outcomes, the status of the match, and period, set, or inning splits when the sport uses them and your scope includes them.
Relevant to
Newsrooms, league operations, and sportsbook or media desks that need the result rather than a written story.
Arrives as
A structured file on the cadence we agree. This page does not update a score.

02

Fixtures

Contains
The scheduled encounter, the participants, the competition name, and the start context you ask us to carry.
Relevant to
Slate builders, graphics desks, and anyone planning coverage before the event begins.
Arrives as
A file ahead of the event, refreshed if we agree that postponements and moved starts belong in the scope.

03

Live events

Contains
Ordered in-play actions for the sports in your scope: goals, points, cards, substitutions, and the comparable events in other sports.
Relevant to
Broadcast, sportsbook, and analytics desks that mark the match while it is being played.
Arrives as
In-play events on the cadence we confirm in writing. "Live" describes the record, not a socket open in this browser, and not a promised speed.

04

Player and team reference

Contains
Names, teams, roles, and stable identifiers for the people and clubs in the competitions you select.
Relevant to
Analysts and product teams joining DataGuru files to systems they already run.
Arrives as
A reference file you can refresh when rosters change, on a schedule we set together.

05

Historical results

Contains
Completed matches for a window you name, with the scores and context fields written into the scope.
Relevant to
Backfills, research, and models that need a settled record rather than the match in progress.
Arrives as
A one-time file or a rolling history. The window is agreed before we send it.

Formats are agreed in the scope. JSON and CSV are the usual path. If you need a different package, ask, and we will confirm it before any data moves.
